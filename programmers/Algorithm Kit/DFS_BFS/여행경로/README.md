# 여행경로

## 알고리즘 분류

- 깊이 우선 탐색(DFS)
- 백트래킹
- 정렬
- 해시 맵

## 문제 정의

`ICN`에서 출발하여 주어진 항공권을 모두 정확히 한 번씩 사용하는 여행 경로를 구한다.
가능한 경로가 여러 개라면 공항 이름을 이어 붙여 비교했을 때 알파벳 순으로 가장 앞서는 경로를 반환해야 한다.

## 풀이 기록

### v1

#### 풀이 아이디어

항공권 한 장을 방향이 있는 간선으로 보고, 현재 공항에서 사용할 수 있는 항공권을 하나씩 선택하며 DFS를 수행한다.

같은 출발지와 도착지를 가진 항공권이 여러 장 존재할 수 있으므로 공항 이름이 아니라 **항공권의 인덱스**를 기준으로 사용 여부를 관리한다. `used[i]`는 `i`번째 항공권을 현재 경로에서 이미 사용했는지를 나타낸다.

사전 순으로 가장 앞서는 경로를 먼저 탐색하기 위해 항공권을 출발지와 도착지 순서로 정렬한다. 정렬된 항공권의 인덱스를 출발 공항별로 `Map<String, List<Integer>>`에 저장하면, 현재 공항에서 출발할 수 있는 항공권만 알파벳 순서대로 확인할 수 있다.

탐색 중 모든 항공권을 사용했다면 현재 경로가 사전 순으로 가장 앞서는 유효한 경로이므로 탐색을 종료한다. 항공권이 남아 있는데 더 이동할 수 없다면 직전 선택을 취소하고 다른 항공권을 탐색한다.

#### 알고리즘 풀이

1. 항공권을 출발 공항 오름차순, 도착 공항 오름차순으로 정렬한다.
2. 각 출발 공항을 키로 하고, 해당 공항에서 출발하는 항공권 인덱스 목록을 값으로 하는 맵을 만든다.
3. 출발지가 `ICN`인 항공권을 사전 순서대로 선택한다.
4. 선택한 항공권을 사용 처리하고, `ICN`과 도착 공항을 경로에 추가한 뒤 DFS를 시작한다.
5. DFS에서는 현재 경로의 마지막 공항을 확인한다.
6. 현재 공항에서 출발하는 미사용 항공권을 순서대로 선택한다.
7. 항공권을 사용 처리하고 도착 공항을 경로에 추가한 뒤 재귀 호출한다.
8. 모든 항공권을 사용했다면 `found`를 `true`로 변경하고 완성된 경로를 유지한 채 탐색을 종료한다.
9. 유효한 경로를 완성하지 못했다면 추가했던 공항을 제거하고 항공권의 사용 상태를 복구한다.
10. 탐색이 끝나면 덱에 저장된 경로를 배열로 변환하여 반환한다.

#### 시간복잡도

항공권의 개수를 `N`이라고 하자.

- 항공권 정렬: `O(N log N)`
- 출발 공항별 인덱스 맵 생성: `O(N)`
- DFS 백트래킹: 최악의 경우 `O(N!)`

각 단계에서 선택할 수 있는 여러 항공권의 순서를 조합하여 탐색할 수 있으므로, 최악의 경우 가능한 항공권 순열에 가까운 수의 경로를 확인한다.

따라서 전체 시간복잡도는 다음과 같다.

```text
O(N log N) + O(N) + O(N!)
→ O(N!)
```

정렬 덕분에 사전 순으로 가장 앞서는 완성 경로를 찾으면 즉시 종료하므로 실제 탐색량은 입력 구조에 따라 줄어들 수 있다.

#### 공간복잡도

```text
O(N)
```

- 항공권 인덱스를 저장하는 맵: `O(N)`
- 항공권 사용 여부 배열: `O(N)`
- 여행 경로를 저장하는 덱: `O(N)`
- DFS 재귀 호출 스택: `O(N)`

각 자료구조의 사용량을 합쳐도 항공권 수에 비례하므로 전체 공간복잡도는 `O(N)`이다.

#### 개선 가능한 부분

- `ICN`에서 출발하는 항공권을 바깥 반복문에서 별도로 선택하기보다, 경로에 `ICN`만 먼저 넣고 `dfs(0)`을 호출하면 시작 지점과 이후 탐색을 같은 로직으로 처리할 수 있다.
- DFS가 성공 여부를 `boolean`으로 반환하도록 만들면 전역 상태인 `found` 없이도 탐색 종료 여부를 명확하게 전달할 수 있다.
- 현재 구현은 전달받은 `tickets` 배열을 직접 정렬한다. 입력값을 변경하지 않아야 하는 상황이라면 복사본을 만든 뒤 정렬할 수 있다.
- 항공권 수가 크고 분기 수가 많은 경우 백트래킹 탐색량이 커질 수 있다. 모든 간선을 한 번씩 사용하는 오일러 경로의 성질을 이용한 Hierholzer 알고리즘으로 개선하면 정렬을 포함하여 `O(N log N)`에 해결할 수 있다.

#### 시행착오

- 처음에는 DFS에서 선택한 항공권의 `used` 값을 변경하지 않아 같은 항공권을 반복해서 사용할 수 있었다.
  - 원인: 경로에 도착 공항만 추가하고 항공권 자체의 사용 상태는 기록하지 않았다.
  - 해결: 재귀 호출 전에 `used[i] = true`, 실패하여 되돌아올 때 `used[i] = false`로 복구했다.
  - 이후 주의할 점: 중복된 항공편이 존재할 수 있으므로 공항 이름이 아닌 항공권 인덱스로 방문 여부를 관리해야 한다.
- 완성된 경로를 찾은 뒤에도 백트래킹 코드가 실행되어 경로의 공항이 제거되는 문제가 있었다.
  - 원인: 재귀 호출 직후 성공 여부를 확인하지 않고 항상 덱의 마지막 원소를 제거했다.
  - 해결: 재귀 호출 후 `found`가 `true`이면 즉시 반환하여 완성된 경로를 유지했다.
  - 이후 주의할 점: 백트래킹에서는 성공한 상태를 보존해야 하는지, 탐색을 계속하기 위해 상태를 복구해야 하는지 구분해야 한다.
- 현재 공항에서 출발하는 항공권이 없을 때 맵에서 얻은 값이 `null`이 될 수 있었다.
  - 원인: 막다른 경로도 DFS 과정에서 발생할 수 있다는 점을 처리하지 않았다.
  - 해결: `map.containsKey(current)`를 확인하고 출발 가능한 항공권이 없다면 현재 탐색을 종료했다.
