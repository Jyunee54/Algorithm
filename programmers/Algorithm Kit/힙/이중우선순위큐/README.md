# 이중우선순위큐

## 알고리즘 분류

균형 이진 탐색 트리, TreeMap, 우선순위 큐

## 풀이 기록

### v1

#### 문제 정의

숫자 삽입, 최댓값 삭제, 최솟값 삭제 연산을 모두 처리한 뒤 남은 원소의 최댓값과 최솟값을 반환한다. 같은 값이 여러 번 삽입될 수 있으며, 빈 큐에 대한 삭제 연산은 무시해야 한다.

#### 풀이 아이디어

삽입과 함께 최솟값과 최댓값을 모두 빠르게 찾아 삭제해야 한다. Java의 `TreeMap`은 키를 오름차순으로 유지하는 균형 이진 탐색 트리이므로 삽입과 삭제를 O(log M), 최솟값과 최댓값 조회를 O(log M)에 처리할 수 있다. 여기서 M은 현재 저장된 서로 다른 값의 개수다.

`TreeMap<Integer, Integer>`에서 키는 삽입된 숫자, 값은 해당 숫자의 등장 횟수로 사용한다. 이렇게 하면 중복된 값을 모두 개별 노드로 저장하지 않고도 정확한 삽입과 삭제를 처리할 수 있다.

- `I 숫자`: 해당 숫자의 개수를 1 증가시킨다.
- `D 1`: `lastKey()`로 최댓값을 찾아 하나 삭제한다.
- `D -1`: `firstKey()`로 최솟값을 찾아 하나 삭제한다.
- 삭제할 값의 개수가 1이면 키를 제거하고, 2 이상이면 개수만 1 감소시킨다.

#### 알고리즘 풀이

1. 빈 `TreeMap<Integer, Integer>`을 생성한다.
2. `operations`를 순회하며 각 명령을 연산 문자와 숫자로 분리한다.
3. 삽입 명령이면 `getOrDefault()`로 기존 개수를 조회해 1 증가시킨다.
4. 삭제 명령이면 먼저 맵이 비어 있는지 확인한다.
   - 명령 값이 `1`이면 `lastKey()`로 최댓값을 선택한다.
   - 명령 값이 `-1`이면 `firstKey()`로 최솟값을 선택한다.
   - 선택한 값이 하나만 남았으면 키를 제거하고, 여러 개라면 개수를 1 줄인다.
5. 모든 연산을 처리한 후 맵이 비어 있으면 `[0, 0]`을 반환한다.
6. 맵이 비어 있지 않으면 `[lastKey(), firstKey()]`, 즉 `[최댓값, 최솟값]`을 반환한다.

#### 시간복잡도

O(N log M)

- N은 전체 연산의 개수이고, M은 `TreeMap`에 저장된 서로 다른 값의 최대 개수다.
- 각 삽입과 삭제, `firstKey()` 또는 `lastKey()` 조회에 O(log M)이 필요하다.
- 전체 N개의 명령을 처리하므로 O(N log M)이며, 최악의 경우 M ≤ N이므로 O(N log N)이다.

#### 공간복잡도

O(M)

- `TreeMap`에 서로 다른 값과 각 값의 개수를 저장한다.
- 모든 삽입값이 다르면 M = N이므로 최악의 경우 O(N)이다.

#### 개선 가능한 부분

- `operation.split(" ")`는 명령을 처리할 때마다 정규식 기반의 문자열 분할과 배열 생성을 수행한다. 연산의 개수가 많을 수 있으므로 `operation.charAt(0)`으로 명령을 구분하고 `operation.substring(2)`를 정수로 변환하면 불필요한 객체 생성을 줄일 수 있다.
- `delete()` 내의 두 번째 조건문은 `else if (num == -1)`로 작성하면 삭제 명령이 두 경로 중 하나만 실행된다는 사실이 더 명확해진다.
- 최소 힙과 최대 힙을 함께 사용하는 방법도 있지만, 한쪽에서 삭제한 원소를 다른 힙에서도 동기화해야 한다. 현재의 `TreeMap`을 이용한 풀이가 더 단순하면서도 동일한 O(N log N) 시간복잡도를 보장한다.

#### 시행착오 및 주의할 점

- `TreeSet`만 사용하면 중복값이 하나로 합쳐져 같은 값을 여러 번 삽입한 경우를 올바르게 처리할 수 없다. 값별 등장 횟수를 함께 저장해야 한다.
- 개수가 0이 된 키를 맵에 남겨 두면 `firstKey()`나 `lastKey()`가 실제로는 존재하지 않는 값을 반환할 수 있다. 남은 개수가 1일 때는 반드시 키 자체를 제거해야 한다.
- 빈 맵에서 `firstKey()`나 `lastKey()`를 호출하면 예외가 발생하므로, 삭제하기 전과 최종 결과를 만들기 전에 `isEmpty()`를 확인해야 한다.
